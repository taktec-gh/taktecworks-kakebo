## 設計判断（先に決めておくこと）

### 並べ替えロジックは共通化する

カテゴリの並べ替えは払い出し先とまったく同じ構造になる。「表示するグループ → 隠すグループの順」「移動は同一グループ内のみ」「`sortOrder` は 1 からの連番」。違うのはグループ分けのフラグだけ（払い出し先は `isActive`、カテゴリは `isHidden`）。

**同じロジックを2つ書かない。** 汎用モジュール（例: `src/lib/ordering.ts`）に切り出し、払い出し先とカテゴリの両方がそれを使う形にする。Step 3 の境界判定は変異テストで4箇所の欠陥を検出できた実績があり、これを2箇所に複製すると片方だけ壊れる余地が生まれる。

**ただし `src/lib/payment-source-order.ts` の公開インターフェース（関数名・引数・戻り値）は変えないこと。** Step 3 のテストがそのまま通る状態を保つ。中身を汎用モジュールへの委譲に置き換えるのは構わない。既存テストが1件でも落ちたら、それは共通化の失敗なのでレポートすること。

### カテゴリの削除は払い出し先と同じ規則

`Expense` も `CategoryBudget` も参照していないカテゴリに限り削除を許す。参照があれば拒否して「非表示にしてください」と案内する。

`CategoryBudget` は `onDelete: Cascade` なので、予算が付いたまま消すと予算が黙って消える。**カテゴリ予算が1件でもあれば削除は拒否する。**

カテゴリに `isDefault` は無い（既定という概念があるのは払い出し先だけ）。**「最後の1件は消せない」という制限も設けない** — 支出登録にカテゴリは必要だが、利用者がすべて非表示にしたなら意図的な操作であり、Step 5 の支出登録画面で「カテゴリがありません」と案内すればよい。

### 予算の主軸は払い出し先。カテゴリ予算は合計に足さない

features.md「設計判断 > 予算の持ち方」のとおり。

- **総予算 = その月の `Budget`（払い出し先の予算）の合計。** 総予算を別途手入力する欄は作らない
- **`CategoryBudget` は任意の補助上限であり、総予算には一切足さない。** 足すと二重計上になる。画面上でも別のセクションに分け、「総予算には含まれません」と明示する

### 予算の「未設定」と「0円」を区別する

- 入力欄が空 = **未設定**。`Budget` レコードを作らない（すでにあれば削除する）
- `0` を入力 = **0円の予算**としてレコードを作る

合計の計算上はどちらも 0 だが、画面表示で「未設定」と「¥0」を区別する。予算を入れ忘れているのか、意図的に0にしたのかが分からないと使えないため。

### 無効な払い出し先に予算が残っている場合

払い出し先を無効化しても、過去に設定した `Budget` は残る。

- **合計には、その月の `Budget` レコードをすべて含める**（払い出し先の有効・無効に関わらず）。合計から黙って除外すると、画面の合計と実際のデータが食い違う
- 入力欄として並べるのは**有効な払い出し先のみ**
- 無効な払い出し先に予算が残っている場合は、警告付きで別途表示し、その場で削除できるようにする

### 月の決定は JST 固定

「今月」を求める処理は必ず純粋関数に切り出し、**現在時刻を引数で受け取れる**ようにする。`new Date()` を関数の中で直接呼ばない。月末・年またぎの境界がテストできなくなるため。

例: `getCurrentYearMonth(now: Date): string`、`shiftYearMonth(yearMonth: string, months: number): string`

`.claude/agents/implementer.md` の規約どおり **JST 固定**。UTC で計算すると日本時間の月初9時間が前月に落ちる。

### 収入（Income）はこのStepでは扱わない

`Income` モデルは Step 2 で作ってあるが、入力UIは **Step 6（ダッシュボード）で作る**。ダッシュボードで「今月使える原資」として表示するときに、同じ画面で入力できるほうが自然なため。このStepでは触らない。

### 前月の予算をコピーする機能は作らない

便利ではあるが features.md にない。実際に毎月手入力してみて面倒だと分かってから足す。使う前に想像で機能を増やさない。

## 実装内容

### 1. 並べ替えの共通化

`src/lib/ordering.ts`（名前は任意）に、グループ分けのフラグを外から与えられる形で切り出す。`src/lib/payment-source-order.ts` はこれに委譲する薄い層にする。

### 2. カテゴリ管理

払い出し先（Step 3）と同じ構造で作る。

| ファイル | 内容 |
|---|---|
| `src/lib/category-validation.ts` | 名前（前後 `trim`、1〜20文字、コードポイント単位）、`costType` の検証 |
| `src/lib/categories.ts` | データ層。`PrismaClient` を引数で受け取る |
| `src/app/settings/categories/` | 一覧 + 追加、編集ページ |

操作: 一覧 / 追加 / リネーム / 固定費・変動費の変更 / 並べ替え / 非表示・再表示 / 削除（参照ゼロのときのみ）。

名前は20文字（払い出し先は30文字）。カテゴリ名は「食費」「日用品」のように短く、一覧で並べたときに折り返さないほうが読みやすいため。

### 3. 月次予算

| ファイル | 内容 |
|---|---|
| `src/lib/year-month.ts` | `"YYYY-MM"` の生成・前後移動・妥当性検証（純粋関数、JST固定） |
| `src/lib/budget-calculation.ts` | 合計・未設定の判定（純粋関数、DB非依存） |
| `src/lib/budgets.ts` | データ層 |
| `src/app/budgets/` | 予算画面 |

**画面（`/budgets`）**

- 対象月の表示と「前月 / 翌月」の移動。既定は今月（JST）
- **払い出し先の予算**（主軸）: 有効な払い出し先ごとに金額入力欄。**合計をその場で大きく表示**する
- **カテゴリ予算**（任意）: 別セクション。「設定しなくても構いません。総予算には含まれません」と明示する
- 無効な払い出し先に予算が残っている場合の警告表示と削除

**金額の入力規則**
- 整数円のみ。小数・カンマ・全角数字は拒否するか正規化するかを決めてレポートに書く
- 範囲は **0 以上 99,999,999 以下**。上限は打ち間違い（桁の入れすぎ）を検出するため
- 空欄は「未設定」

保存は payment source ごとの個別保存でも一括保存でもよいが、**スマホで金額を3つ入れて1回で保存できる**ほうが速い。判断して理由をレポートに書くこと。

### 4. 導線

`src/app/page.tsx` から `/budgets` と `/settings/categories` へ辿れるようにする。

### Step 3 との違い

- 予算の Server Action の state は **`{ error: string | null; saved: boolean }`**（カテゴリ側は Step 3 と同じ `{ error }` のみ）
- 月は **`?month=YYYY-MM`** のクエリで受け渡す。不正値・未指定は今月（JST）に落とし、エラー画面にはしない
- 予算の保存はセクション単位の**一括保存**。`saveBudgetsAction` は `formData.has(フィールド名)` が真の行だけを保存対象にする

### 特に確認したい観点

仕様上こわれると被害が大きい順。

1. **`getCurrentYearMonth` の JST 境界** — `2026-08-31T15:00:00Z`（JST 9/1 0:00）が `"2026-09"`、`2026-08-31T14:59:59Z` が `"2026-08"`。UTC 実装だと落ちる
2. **総予算に `CategoryBudget` が混ざらないこと** — features.md「予算の持ち方」の主従が壊れると二重計上になる
3. **無効な払い出し先の予算が `totalYen` に含まれ、入力欄（`rows`）には含まれないこと** — 合計から黙って除外すると画面と実データが食い違う
4. **`amountYen: 0` と `null`（未設定）が区別されること** — 合計上はどちらも0だが意味が違う
5. **`saveBudgetsAction` が `formData.has` で行を選ぶこと** — フィールドが無い払い出し先の予算を消してしまわないこと。消えると過去の設定が黙って飛ぶ
6. **`saveBudgets` が、月・金額が不正なときに DB を一切呼ばないこと**。`null` は削除・数値は upsert で、**1回の `$transaction`** に渡ること
7. **`ordering.ts` のグループ境界**（Step 3 と同じ観点）と、**払い出し先とカテゴリが同じ規則で動くこと**。共通化が片方だけ壊れていないことを両方で確かめる
8. **`parseBudgetAmountInput` の正規化と拒否** — 全角数字・桁区切りカンマは受け入れ、小数・マイナス・指数表記は拒否。上限 99,999,999
9. **`shiftYearMonth` の年またぎと範囲端**（`RangeError`）
10. **`deleteCategory` の判定順**（支出 → カテゴリ予算）と、削除後に残りが 1..n へ再採番されること
11. 全 Server Action が先頭で `getSession()` を呼び、null なら `/login` へ redirect すること

### テストの方針

Step 2・Step 3 と同じ。**単体テストから実データベースに接続しない。**
